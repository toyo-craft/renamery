バッチリネームソフト「Namery」再実装詳細設計書

ご提示いただいた資料に基づき、特に「Namery」の仕様を忠実に再現しつつ、現代のWindows環境（Windows 10/11）で安全に動作させるための**詳細機能設計書**を作成しました。

ご要望のあった「各機能タブの詳細仕様」および「アンドゥ・リドゥ（やり直し）」「セーフティ機構（安全装置）」に重点を置いて記述します。

--------------------------------------------------------------------------------

バッチリネームアプリケーション詳細設計書（Namery再実装版）

1. ユーザーインターフェース詳細設計

基本構成は「3ペイン方式」を維持し、視線の移動を最小限に抑える効率的なレイアウトとする[1, 2]。

• **左ペイン（ソース選択）**:

    ◦ **フォルダツリー**: エクスプローラー互換の階層表示。

    ◦ **下位フォルダ検索**: チェックボックスにより、選択フォルダ以下のサブディレクトリ内の全ファイルを再帰的にリストアップする機能を実装する[3]。

• **中央ペイン（操作対象リスト・プレビュー）**:

    ◦ **グリッドカラム**: 「現在のファイル名」「変更後のファイル名（リアルタイムプレビュー）」「拡張子」「ファイルサイズ」「更新日時」「パス（下位検索時）」[4]。

    ◦ **手動ソート機能**: カラムヘッダーによるソートに加え、ドラッグ＆ドロップまたはツールバーの「↑」「↓」ボタンでリスト内の順序を任意に入れ替え可能とする。これは後述の「連番処理」の順序を決定するために必須である[4, 5]。

• **右ペイン（リネームルール設定）**:

    ◦ 4つのタブ（Main, Sub, Extra, etc）による機能切り替え[6]。

2. リネームロジック詳細仕様（タブ別）

2.1 Mainタブ：文字列操作と連番（中核機能）

ファイル名の主要部分（Body）に対する操作を行う[7]。

1. **文字列置換 (Replace)**

• **入力**: 「検索文字列」「置換文字列」

• **挙動**: ファイル名に含まれる対象文字列をすべて新しい文字列に置換する。空白削除（空白→空文字）や、特定文字のアンダースコア化などに使用[8, 9]。

2. **文字列挿入 (Insert/Append)**

• **入力**: 「挿入文字列」、「挿入位置（数値指定）」または「先頭/末尾」ラジオボタン。

• **詳細**: 指定した文字数（例：5文字目）の後ろに文字列を挿入する。負の値（-2文字目など）で末尾からの指定も可能とする[5]。

3. **文字削除 (Truncate)**

• **入力**: 「先頭からX文字削除」「末尾からY文字削除」。

• **用途**: デジカメ画像などで付与される不要なプレフィックス（DSC_など）の除去[7]。

4. **連番付与 (Numbering)**

• **入力**:

    ◦ **開始番号**: 整数（例: 1, 100）。

    ◦ **桁数（パディング）**: ゼロ埋めの指定（例: 3桁→001, 002...）。最大10桁程度まで対応[7]。

    ◦ **付与位置**: 先頭、末尾、指定位置。

• **ハードウェア連携要件**: 音声ペン（カメレオンリーダー等）などの組み込み機器向けに、厳密な「5桁連番（00001.mp3）」などを生成できる仕様とする[7, 10]。

5. **ケース変換 (Case)**

• **選択肢**: 「全て大文字」「全て小文字」「先頭のみ大文字」[11]。

2.2 Subタブ：拡張子と高度な整形

拡張子（Extension）および特殊なフォーマット操作を行う[12]。

1. **拡張子操作**

• **変更**: 拡張子を任意の文字列に置換する（例: .jpeg → .jpg）。

• **削除**: 拡張子を削除する。

• **追加**: 拡張子がないファイルに付与する[12, 13]。

2. **拡張子ケース変換**

• ファイル名本体とは独立して、拡張子のみを「小文字/大文字」に統一する（Webサーバーアップロード用などで重要）[5, 8]。

3. **単語整形 (Word Shaping)**

• **機能**: スペースやアンダースコアで区切られた単語の先頭文字のみを大文字化する（例: `my_document.txt` → `My_Document.txt`）[12]。

4. **リスト取り込み機能**

• **機能**: 外部のテキストファイル（改行区切り）を読み込み、リストの上から順にファイル名を適用する。データベースなどとの照合用[12]。

2.3 Extraタブ：メタデータと日本語処理

日付情報と文字コード（全角/半角）変換を行う[14]。

1. **日時挿入**

• **ソース**: 「作成日時」「更新日時」から選択。

• **フォーマット**: YYYYMMDD、YY-MM-DDなどをプルダウンまたは書式指定文字で選択し、ファイル名の先頭または末尾に付与する[15, 16]。

2. **文字種変換（日本語対応）**

• **全角⇔半角**: 全角英数カナを半角へ、またはその逆。レガシーシステムやアーカイブデータの正規化に必須[16, 17]。

• **ひらがな⇔カタカナ**: 日本語ファイル名の揺らぎ補正。

2.4 etcタブ：属性とタイムスタンプ

ファイルシステムレベルのメタデータを操作する[18]。

1. **属性変更**: Read-only（読み取り専用）、Hidden（隠し）、System（システム）の各属性のON/OFF切り替え[18]。

2. **タイムスタンプ変更**: 任意の「作成日時」「更新日時」を一括適用する。写真整理等で撮影日とファイル作成日がずれた場合の補正に使用[16]。

3. アンドゥ・リドゥおよびセーフティ機構設計

本アプリケーション最大の要件である「安全性」を担保するための設計です。

3.1 リアルタイムプレビュー機構 (Safety Level 1)

ユーザーが設定を変更した瞬間（キー入力イベント、クリックイベント）、ディスクへの書き込みを行わずに計算のみを行い、中央ペインの「変更後のファイル名」カラムを更新する[19]。

• **エラー事前検知**: 変換の結果、ファイル名に使用できない文字（`\ / : * ? " &lt; &gt; |`）が含まれる場合や、同名ファイルが発生する場合は、該当行を赤色でハイライト表示し、実行ボタンを非活性化する。

3.2 トランザクション型実行とアンドゥ機能 (Safety Level 2)

「Go Namery!!」ボタン押下時の処理フローと、アンドゥ（Undo）の実装詳細です[20, 21]。

1. **実行前スナップショット**:

• リネーム実行直前に、対象となる全ファイルの「フルパス（変更前）」と「フルパス（変更後）」のペアをメモリ上のスタック（Undo Stack）に保存する。

2. **実行処理**:

• ファイル名の変更処理を順次実行する。

3. **アンドゥ（戻す）処理**:

• ツールバーの「戻す」ボタンが押下された場合、スタックから直前の操作ログを取り出す。

• ログを**逆順**（新しい名前 → 古い名前）に走査し、`Rename(current, original)`を実行して状態を復元する[20]。

• **制限事項**: ファイルが移動または削除されていた場合、そのファイルのアンドゥはスキップし、ログにエラーを出力する。

3.3 競合回避ロジック (Conflict Resolution)

リネームの結果、同一フォルダ内に同名のファイルが存在することになる場合の処理オプションを設定画面で提供する。

• **デフォルト**: エラーとして処理を中断、またはスキップする。

• **自動連番付与**: 重複する場合、自動的に `filename (2).txt` のようにサフィックスを付与して回避する（Flexible Renamer等の挙動を参考）[22]。

4. 技術的実装要件（Windows 10/11対応）

4.1 開発環境と互換性

• **Unicode完全対応**: オリジナル版Nameryの課題であったUnicode文字（絵文字や特殊言語文字）を含むファイル名の取り扱いをネイティブでサポートする[23]。

• **High DPI対応**: 高解像度モニターでのぼやけを防ぐため、UIフレームワーク側でスケーリング設定を有効化する（ManifestファイルでのdpiAware宣言など）[24]。

4.2 設定の永続化

• **ポータブル仕様**: レジストリを使用せず、EXEと同階層のINIファイル（またはJSON）に設定を保存する[25]。

• **起動時フリーズ対策**: オリジナル版の既知の不具合である「存在しないネットワークドライブ等を前回フォルダとして記憶していると起動しない」問題を回避するため、起動時にパスの存在確認を行い、無効な場合はデフォルト（My Documents等）にフォールバックするロジックを実装する[26, 27]。

4.3 パフォーマンス要件

• 数千ファイル単位のリスト表示においてUIがフリーズしないよう、ファイルリストの描画には仮想化リストビュー（Virtual Mode）を採用する。

アナロジーによる機能理解

このアプリケーションの設計思想は、**「ファイルの美容室」**のようなものです。

• **Mainタブ**は「カットやパーマ」：名前そのものの長さを変えたり、形（連番）を整えたりします。

• **Subタブ**は「カラーリング」：拡張子というファイルの種類（色）を変えます。

• **Extraタブ**は「トリートメント」：日付を入れたり、全角半角を整えて質を良くします。

• **アンドゥ機能**は「魔法の鏡」：カットしてしまった後でも、ボタン一つで切る前の状態に時間を巻き戻せる安全装置です。
