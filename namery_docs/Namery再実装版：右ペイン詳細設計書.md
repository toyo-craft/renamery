thoughtful Namery再実装：右ペイン詳細設計書

ご提示いただいた資料およびこれまでの設計プロセスに基づき、Namery再実装版における**右ペイン（ルール設定・ロジックパネル）**の詳細設計書を作成しました。

このペインは、ユーザーがリネームの「規則」を定義するエンジンの役割を果たし、Nameryの最大の特徴である「4つのタブによる機能分割」を忠実に再現します。

--------------------------------------------------------------------------------

右ペイン詳細設計書：リネームルール設定エンジン

1. 概要

右ペインは、ファイル名変更のロジック（規則）をユーザーが入力・設定する領域である。機能の複雑化を防ぐため、**Main, Sub, Extra, etc** の4つのタブにカテゴライズし、目的別の操作環境を提供する[1, 2]。 ここでの入力操作は即座に「変更イベント」を発火させ、中央ペインの「リアルタイムプレビュー」に反映されなければならない[3, 4]。

2. UI構成とタブ別詳細仕様

2.1 Mainタブ：基本文字列操作と連番処理

ファイル名の主要部分（Body）に対する最も頻度の高い操作を集約する[2, 5]。

(1) 文字列置換 (Replace)

• **UI要素**:

    ◦ 「検索文字列」入力フィールド

    ◦ 「置換文字列」入力フィールド

• **ロジック**: ファイル名に含まれる「検索文字列」に一致する部分を、すべて「置換文字列」に書き換える。

• **ユースケース**: 空白スペースをアンダースコア（`_`）に変換する、特定のプロジェクト名を一括修正するなど[6, 7]。

(2) 文字列挿入 (Insert/Append)

• **UI要素**:

    ◦ 「挿入文字列」入力フィールド

    ◦ 「挿入位置」ラジオボタン/スピンボックス

        ▪ 選択肢：`先頭`, `末尾`, `指定位置（X文字目）`

• **ロジック**:

    ◦ 指定された位置に文字列を挿入する。

    ◦ 既存のファイル名文字列のインデックス（1始まり）を指定可能とする（例：5文字目に挿入）[7]。

(3) 文字削除 (Truncate/Cut)

• **UI要素**:

    ◦ 「先頭から削除数」スピンボックス

    ◦ 「末尾から削除数」スピンボックス

    ◦ 「指定範囲削除」入力（開始位置、終了位置）

• **ロジック**: 指定された文字数分、ファイル名の文字を削除する。ファイル名が指定数より短い場合の例外処理（空文字にするか、エラーとするか）を実装する[6]。

(4) 連番付与 (Numbering)

ハードウェア（音声ペン等）連携において最も重要な機能である[5, 8]。

• **UI要素**:

    ◦ 「開始番号」入力（例: 1, 100）

    ◦ 「桁数（パディング）」スピンボックス（例: 3 → 001, 002...）

    ◦ 「付与位置」選択（ファイル名の先頭/末尾/置換）

    ◦ 「接続文字」入力（連番の前に付与する文字。例: `_` や `-`）

• **ロジック**:

    ◦ 中央ペインのリスト順に従って連番を生成する[6]。

    ◦ **重要**: カメレオンリーダー等の仕様に合わせ、最大5桁～10桁程度のゼロ埋め（`00120.mp3`等）を正確にサポートする[9]。

(5) ケース変換

• **UI要素**: ラジオボタン（全て大文字 / 全て小文字 / 先頭のみ大文字）

• **ロジック**: 拡張子を除くファイル名部分のアルファベットを変換する[6, 10]。

--------------------------------------------------------------------------------

2.2 Subタブ：拡張子と整形

拡張子（Extension）およびリストベースの高度な処理を行う[6, 11]。

(1) 拡張子操作

• **UI要素**:

    ◦ 「モード選択」ラジオボタン（変更 / 削除 / 追加）

    ◦ 「拡張子文字列」入力フィールド

• **ロジック**:

    ◦ **変更**: 既存の拡張子を新しいものに置換する（例: `.jpeg` → `.jpg`）[12]。

    ◦ **削除**: 拡張子を取り除く。

    ◦ **追加**: 拡張子がないファイルにのみ付与する安全策を講じる。

(2) 拡張子ケース変換

• **UI要素**: ラジオボタン（大文字化 / 小文字化）

• **ロジック**: ファイル名本体とは独立して、拡張子部分のみを変換する[6]。Webサーバーへのアップロード前の正規化（`.JPG` → `.jpg`）に使用される[12]。

(3) 単語整形 (Word Shaping)

• **機能**: 区切り文字（スペース、ドット、アンダースコア）で区切られた単語を認識し、各単語の先頭文字を大文字にする（Title Case化）。

    ◦ 例: `my_document.txt` → `My_Document.txt` [6, 11]。

(4) リスト取り込み

• **UI要素**: 「リスト読み込み」ボタン、「適用」ボタン。

• **ロジック**: 外部テキストファイル（改行区切り）を読み込み、中央ペインのファイルリストに対し、上から順に新しい名前を割り当てる[11]。データベース出力との照合などに利用。

2.3 Extraタブ：メタデータと文字種変換

日本語環境およびアーカイブ整理に特化した機能群[4, 13, 14]。

(1) 日時挿入

• **UI要素**:

    ◦ 「対象日時」選択（作成日時 / 更新日時）

    ◦ 「フォーマット」プルダウン（`YYYYMMDD`, `YY-MM-DD`, `YYMMDD_HHMM` 等）

    ◦ 「挿入位置」選択（先頭 / 末尾）

• **ロジック**: ファイルシステムのタイムスタンプを取得し、文字列化してファイル名に付加する。デジカメ写真整理等の「いつ撮ったか」をファイル名に残す用途[4, 13]。

(2) 文字種変換（日本語処理）

• **UI要素**: チェックボックス群

    ◦ 全角英数 → 半角英数

    ◦ 半角英数 → 全角英数

    ◦ 全角カナ → 半角カナ

    ◦ ひらがな ⇔ カタカナ

• **ロジック**:

    ◦ 日本語特有の文字コード変換を行う。

    ◦ **重要**: サーバー移行やレガシーシステム連携において、全角ファイル名を半角に正規化する機能は必須要件である[14-16]。

--------------------------------------------------------------------------------

2.4 etcタブ：属性とタイムスタンプ操作

ファイルシステムレベルのメタデータ書き換え機能[14, 17]。

(1) 属性変更

• **UI要素**: チェックボックス（読み取り専用 / 隠しファイル / システムファイル / アーカイブ）

• **ロジック**: Windowsのファイル属性（Attribute）をON/OFFする。

(2) タイムスタンプ変更

• **UI要素**: 日時指定ピッカー（作成日時 / 更新日時 / アクセス日時）

• **ロジック**: ファイル自体のタイムスタンプを指定した日時に書き換える。写真のExif情報とファイル作成日がずれてしまった場合の補正などに使用する。

3. インタラクション設計

3.1 リアルタイムプレビュー連携

• 右ペイン内の入力フィールド（テキストボックス）でキー入力があるたび（`OnKeyUp`）、またはラジオボタン等の変更があるたび（`OnChange`）、イベントを発火させる。

• このイベントをトリガーとして、中央ペインの「変更後のファイル名」カラムを再計算・再描画する[3, 4]。

• **パフォーマンス考慮**: テキスト入力毎の再計算が重い場合（数千ファイル時など）、入力完了後300ms程度のデバウンス（遅延実行）処理を入れる。

3.2 プリセット保存（お気に入り）

• 右ペイン全体の設定状態を「プロファイル」として保存・呼び出しできる機能を実装する。

• Nameryの強みである「よく使うリネームパターン」を再現するため、設定値（Mainの連番設定、Extraの日付設定など）をXMLまたはJSON形式でエクスポート/インポート可能にする[18]。

4. 既存ツールとの比較・差別化

• **対 Flexible Renamer**: Flexible Renamerは正規表現やExif/ID3タグの詳細な利用（タグ・リネーム）に強みを持つが[19-22]、本設計（Namery再現）ではそれらをあえて排除または簡素化し、**「直感的な連番付与」や「位置指定挿入」の使いやすさ**に特化する。

• **対 極窓**: 拡張子の判別・修正機能は持たせず、あくまで「命名規則の変更」に注力する[23]。

この右ペイン設計により、ユーザーは複雑な正規表現を覚えることなく、タブを切り替えるだけで「頭に日付をつけて」「連番を振って」「拡張子を小文字にする」といった複合的な操作を迷いなく実行できます。
