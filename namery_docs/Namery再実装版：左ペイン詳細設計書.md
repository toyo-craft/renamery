Namery再実装版：左ペイン詳細設計書

ご提示いただいた資料に基づき、アプリケーション（Namery再実装版）における**左ペイン（ナビゲーション・プレビューエリア）**の詳細設計書を作成しました。

このペインは、ユーザーがリネーム対象のファイル群を探索・特定し、視覚的に確認するための「入り口」となる重要な領域です。

--------------------------------------------------------------------------------

左ペイン詳細設計書：ナビゲーションおよび探索インフラ

1. 概要

左ペインは、アプリケーションの「探索と発見（Navigation and Discovery）」を担う領域である[1]。ユーザーはここで対象ディレクトリを選択し、必要に応じて下位フォルダを含めた範囲指定を行い、画像等のファイル内容を目視確認する。

2. UIコンポーネント構成

左ペインは垂直方向に分割された2つのエリア（またはタブ切り替え）で構成される。

2.1 上部：ディレクトリツリービュー (Folder Tree)

• **表示形式**: Windowsエクスプローラー互換の階層型ツリー表示を採用する[1][2]。

• **アイコン表示**: システムアイコンを使用し、フォルダ、ドライブ、デスクトップ、ネットワークなどの標準的なノードを表示する。

• **操作**: シングルクリックで中央ペイン（ファイルリスト）に対象フォルダ内のファイルをロードする[3]。

2.2 中部：検索オプション・フィルタ (Search Options)

ツリービューとプレビューエリアの中間、またはツールバー直下に以下の制御系を配置する。

• **「下位フォルダ検索」チェックボックス**:

    ◦ **機能**: チェックを入れると、選択したフォルダ直下だけでなく、その内部に含まれるすべてのサブフォルダ（下位層）内のファイルを再帰的に検索し、中央ペインのリストに追加する[2][3]。

    ◦ **表示挙動**: この機能が有効な場合、中央ペインのパス表示はルートからの相対パス（例：`\test`）などを表示し、構造を明確にする[3]。

• **フィルタリング（拡張子指定）**:

    ◦ 特定のファイル形式（例：`*.jpg`, `*.mp3`）のみをリストアップするための入力フィールドまたはドロップダウンメニューを配置する[2]。

2.3 下部：プレビューウィンドウ (Preview Window)

• **表示領域**: 選択中のファイルの中身を表示するエリア[1]。

• **対象**: 画像ファイル（JPG, PNG等）を中心に、テキストファイル等の簡易表示をサポートする。

• **目的**: 「DSC_001.jpg」のようにファイル名だけでは内容が判別できないファイルについて、リネーム前に視覚的に内容を特定するために使用する[1][3]。

3. 機能要件とロジック

3.1 ディレクトリ走査ロジック

• **高速化**: フォルダ選択時、数千ファイル規模のディレクトリであってもUIをフリーズさせないよう、ファイル列挙処理は非同期（バックグラウンドスレッド）で実行する。

• **隠しファイル対応**: エクスプローラーの設定に準拠するか、または設定画面（設定ウィンドウ）で隠しファイルの表示/非表示を切り替え可能にする[4]。

3.2 起動時初期化と例外処理（重要）

NameryおよびFlexible Renamerの既知の不具合を解消するための設計を含める。

• **初期フォルダの検証**:

    ◦ 前回終了時のフォルダパスをINIファイル等から読み込む際、そのパス（特にネットワークドライブやリムーバブルディスク）が現存するかをチェックする[5][6]。

    ◦ **フリーズ回避**: パスが存在しない場合、タイムアウトまで待機してフリーズするのを防ぐため、即座にデフォルトパス（例：`My Documents`や`C:\`）にフォールバックするロジックを実装する[7][5][6]。

3.3 プレビュー連携

• **イベント発火**: ユーザーが左ペインのツリー、または中央ペインのリストでファイルを選択したイベントをトリガーとし、左ペイン下部にプレビューを描画する。

• **Susie Plugin対応（オプション）**: オリジナルのNameryが対応していたように、対応フォーマット拡張のためにSusie Pluginなどの外部ライブラリ読み込みインターフェースを検討する[8]。ただし、現代的な実装ではOS標準のコーデック（WIC）利用を優先する。

4. UIデザイン・アクセシビリティ

• **スプリッター制御**: 左ペインと中央ペインの境界、およびツリービューとプレビューの境界は、ユーザーがドラッグしてサイズ変更可能（可変幅）とする。

• **高DPI対応**: Windows 10/11環境において、高解像度モニターでもツリーの文字やアイコンが極小化・ぼやけ等の表示崩れを起こさないよう、DPIスケーリングに対応させる[9]。

5. 既存ツールとの比較・差別化

• **Namery**: 下位フォルダ検索やプレビューが同一画面内にコンパクトに収まっており、視線移動が少ない設計を踏襲する[2]。

• **Flexible Renamer**: 「ターゲット」として「ミュージック」「写真」などのプリセット分類を持つが[10]、本設計（Namery型）ではツリーと拡張子フィルタによる「場所とファイルタイプ」の直接指定を重視し、直感的な操作性を維持する。
