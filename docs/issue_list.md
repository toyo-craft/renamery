# Renamery 課題・修正事項リスト

| ID | 課題内容 | 期待される動作 | 分類 | 優先度 |
| :--- | :--- | :--- | :--- | :--- |
| 001 | フォルダ名を変更できない | ファイルと同様にフォルダのリネームも可能にする | 機能不備 | 高 |
| 002 | ファイルを削除する手段がない | プレビューリストからファイルを削除（リストから除外、または物理削除）する機能を追加する | 機能追加 | 中 |
| 003 | ベータ版機能が常時有効 | 設定画面に「ベータ版機能を有効にする」トグルを追加し、デフォルトはオフにする | 仕様変更 | 中 |
| 004 | サイドパネル変更の即時反映 | サイドパネルの設定値を変更した際、即座に中央パネルの「変更後ファイル名」に反映されるようにする | バグ (UX) | 高 |
| 005 | 「文字列」の初期値 | サイドパネルの「文字列」入力欄は、デフォルトで未入力（空）であるべき | UI/UX | 低 |
| 006 | 複数起動の是非検討 | アプリケーションの二重起動を許可するか、あるいは単一インスタンスに制限するかを検討・実装する | 仕様検討 | 低 |
| 007 | 中央パネルの列ズレ | ヘッダとデータ列の表示位置が一致するように修正する | UIバグ | 中 |

---

## 実行計画 (Execution Plan)

### フェーズ1: UI/UXの改善とバグ修正 (優先度：高)
- **ID 004: サイドパネル変更の即時反映**
  - サイドパネルの各コントローラにリスナーを配置し、変更時に `RenameEngine` を通じてプレビューを再生成する。
- **ID 007: 中央パネルの列ズレ修正**
  - テーブルレイアウトの制約または `Flexible`/`Expanded` の設定を見直し、ヘッダとデータ行で同じ幅計算ロジックを使用するように修正する。
- **ID 005: 「文字列」初期値のクリア**
  - 初期化時のデフォルト値を空文字列に修正。

### フェーズ2: 機能拡張 (優先度：中)
- **ID 001: フォルダ名リネーム対応**
  - `DirectoryProvider` や `FileModel` のロジックを拡張し、ディレクトリもリネーム対象として扱えるようにする。
- **ID 002: ファイル削除機能の実装**
  - リスト上での右クリックメニューまたは削除ボタンを追加し、選択したファイルをリストから除外、あるいはゴミ箱へ移動する機能を実装。
- **ID 003: ベータ版機能フラグの実装**
  - `SettingsService` に `enableBetaFeatures` フラグを追加。UI側でこのフラグを参照し、特定の機能を非表示/無効化する。

### フェーズ3: 仕様検討と最適化 (優先度：低)
- **ID 006: 複数起動の制御**
  - `window_manager` や `single_instance` パッケージ等の利用を検討し、Windows/macOS/Linux 各プラットフォームでの挙動を統一する。
