## 実行計画 (Execution Plan)

### フェーズ1: UI/UXの改善とバグ修正 (優先度：高)

- **ID 004: サイドパネル変更の即時反映**
    - サイドパネルの各コントローラにリスナーを配置し、変更時に `RenameEngine` を通じてプレビューを再生成する。
- **ID 007: 中央パネルの列ズレ修正**
    - テーブルレイアウトの制約または `Flexible`/`Expanded` の設定を見直し、ヘッダとデータ行で同じ幅計算ロジックを使用するように修正する。
- **ID 005: 「文字列」初期値のクリア**
    - 初期化時のデフォルト値を空文字列に修正。

### フェーズ2: 機能拡張 (優先度：中)

- **ID 001: フォルダ名リネーム対応**
    - `DirectoryProvider` や `FileModel` のロジックを拡張し、ディレクトリもリネーム対象として扱えるようにする。
- **ID 002: ファイル削除機能の実装**
    - リスト上での右クリックメニューまたは削除ボタンを追加し、選択したファイルをリストから除外、あるいはゴミ箱へ移動する機能を実装。
- **ID 003: ベータ版機能フラグの実装**
    - `SettingsService` に `enableBetaFeatures` フラグを追加。UI側でこのフラグを参照し、特定の機能を非表示/無効化する。

### フェーズ3: 仕様検討と最適化 (優先度：低)

- **ID 006: 複数起動の制御**
    - `window_manager` や `single_instance` パッケージ等の利用を検討し、Windows/macOS/Linux 各プラットフォームでの挙動を統一する。
