# パフォーマンス改善の実装報告と今後の展望

## 1. はじめに
本ドキュメントは、Renameryにおいて5,000件規模の大量ファイルを高速かつ快適に操作するために実施した一連のパフォーマンス改善施策、および将来的な拡張計画についてまとめたものである。

## 2. 実施済みの主要な高速化施策
現時点までに、以下の「多層的な最適化」を実装済みである。

### A. スキャン・読み込みの極限高速化
*   **バイト列 Isolate スキャン (Windows限定)**:
    Windows環境において `cmd /c dir` コマンドを活用。出力をバイト列のまま Isolate に流し込み、別スレッドで高速にパースすることで、メインスレッドの負荷をゼロにし、読み込み開始速度を数倍に引き上げた。
*   **インクリメンタル表示**:
    全件読み込みを待たず、スキャン中に100件（または50KB）ごとに逐次通知を行うことで、ユーザーへのフィードバックを最速化した。
*   **FileModel の遅延評価 (Lazy Loading)**:
    ファイルサイズ、種類、更新日時など、重いI/Oを伴うプロパティの計算を表示の瞬間まで遅延させ、初期リスト生成時のCPU負荷を劇的に削減した。

### B. プレビュー計算の最適化
*   **仮想化計算 (Lazy Preview)**:
    5,000件全件を計算するのではなく、スクロール位置に連動して「現在見えている範囲（+上下バッファ）」のみを計算対象とする仕組みを導入。
*   **直列キュー（排他制御）**:
    プレビュー計算の Isolate が同時に複数立ち上がるのを防ぐロック機構を実装。計算中に次のリクエストが来た場合は古いものを破棄し、常に最新データで一度だけ再計算するようにした。

### C. UI レンダリングの最適化
*   **レイアウト計算の O(1) 化**:
    `ListView` 内に固定高（`itemExtent` 相当）を指定した `SizedBox` を配置。これにより、数千件あってもスクロール位置の特定が瞬時に行えるようになった。
*   **RepaintBoundary による描画キャッシュ**:
    各行を `RepaintBoundary` で隔離。スクロール時の再描画範囲を最小化し、GPUの負荷を大幅に軽減した。

## 3. 復元された高度な UI/UX 機能
高速化と並行して、以下の重要機能をデグレなく再統合した。
*   **高度なドラッグ＆ドロップ**: 複数選択時のスタック表示、件数バッジ、移動対象のゴースト（透過）表示を完全再現。
*   **正確なラバーバンド選択**: スクロールオフセットを完全に加味した座標計算と、上下端でのオートスクロール機能を実装。
*   **右クリックメニューの排他制御**: ファイル行と背景（空フォルダ、余白）のクリック判定を分離し、適切なメニューを出し分け。
*   **グローバル ESC キャンセル**: ドラッグ、リネーム、選択、切り取りなど、あらゆる一時状態を `ESC` キーで瞬時にリセット可能。

## 4. プラットフォーム別の対応状況
*   **共通（全OS）**: UI最適化、Lazy Preview、Isolateフィルタリング、Lazy Loading。
*   **Windows限定**: バイト列シェルスキャナー（他OSは標準 Isolate スキャンへフォールバック）。

## 5. 今後の展望（将来の実装案）
さらに大規模なデータ、あるいは他OSでの「究極の速度」を実現するためのロードマップ。

### ① 非Windows環境向けネイティブスキャナーの拡張
macOS や Linux においても、`ls` や `find` コマンドを `Process.start` で叩き、バイト列 Isolate 処理を行うことで、全プラットフォームで Windows 同等の読み込み速度を実現する。

### ② 長期生存型 (Persistent) Worker Isolate の導入
現在は `compute`（使い捨て Isolate）を使用しているが、アプリ起動中に常駐する「計算専用スレッド」を確立する。これにより、Isolate の起動・終了コストを完全に排除し、5,000件のリネームプレビューをさらにミリ秒単位で高速化する。

### ③ 適応型デバウンス (Adaptive Debouncing)
操作対象のファイル数に応じて、デバウンス時間（計算開始までの待ち時間）を動的に変更する。数百件なら 20ms、数万件なら 500ms と調整することで、マシンスペックに応じた最適なレスポンスを維持する。

### ④ 属性取得の完全非同期化
現在 `attrib` コマンドで行っている Windows 属性取得を、スキャンとは完全に切り離したバックグラウンドタスクとして非同期実行し、準備ができたファイルから順次アイコンを更新する。

---
本改善により、Renamery は数万件規模のファイル操作に耐えうる、プロフェッショナルなリネームツールとしての基盤を確立した。
