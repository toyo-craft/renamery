# マルチフォーマット非同期プレビュー実装計画

## 1. 目的
リネーム作業の効率化のため、ファイルを選択した際にその中身（テキスト、画像、SVG、PDF、ZIP等）を、操作を妨げない非同期処理で素早くプレビューできる機能を構築します。

## 2. 設計方針
- **完全非同期:** 重いファイルの読み込み中もUIスレッドをブロックせず、スムーズな操作を維持します。
- **リソース管理:** ファイル選択が高速に切り替わった場合、進行中の旧読み込み処理をキャンセルし、メモリ消費を抑えます。
- **部分表示戦略:** 巨大なファイルでも全体を読み込まず、プレビューに必要な先頭部分やメタデータのみを取得します。
- **拡張性:** フォーマットごとに独立した「プレビュー・ウィジェット」を用意し、将来的な形式追加を容易にします。

## 3. 実装フェーズ

### フェーズ 1：非同期プレビュー基盤の構築
- **コンポーネント抽出:** `NavigationPanel` 内のプレビューロジックを `lib/ui/widgets/preview_window.dart`（新設）へ抽出。
- **非同期基盤:** 既存の画像・テキスト表示を新しい非同期基盤の上に移植。
- **検証:** 従来のプレビュー機能が退行（デグレ）していないことを確認。

### フェーズ 2：SVG対応とテキスト部分読み込みの最適化
- **SVG表示:** `flutter_svg` を導入し、ベクター画像の描画に対応。
- **テキスト制限:** 巨大ファイル対策として、読み込み範囲を先頭 2KB 程度に絞り、表示速度を向上。
- **検証:** SVGアイコンや巨大ソースコードのプレビュー速度をデバッグ。

### フェーズ 3：PDF「表紙」レンダリングの実装
- **PDF画像化:** `native_pdf_renderer` を導入。1ページ目のみを画像として非同期生成。
- **検証:** PDF選択時のメモリ使用量とレンダリング時間の確認。

### フェーズ 4：ZIPアーカイブ・サマリー表示
- **ヘッダー解析:** `archive` ライブラリを使用。解凍せずにファイル名一覧（先頭数件）を取得。
- **検証:** 圧縮ファイルの内容がテキスト形式でプレビューされるか確認。

### フェーズ 5：ビジュアル調整と最終ポリッシュ
- **フォントプレビュー:** `.ttf`, `.otf` のサンプル文字列レンダリング。
- **UI調整:** プレビュー領域のサイズ調整、ローディング表示の洗練。
- **最終検証:** 全フォーマットを通した結合テストとパフォーマンス確認。

## 4. デバッグ・フィードバック計画
各フェーズの完了ごとに、以下の手順で進めます。
1.  開発者によるユニットテスト。
2.  ユーザーによる実動作確認とデバッグフィードバック。
3.  フィードバックに基づく修正後、次のフェーズへ移行。
