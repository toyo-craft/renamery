# WEB版 結合テスト観点

## 目的

WEB版で追加したローカルフォルダ連携が、UI、状態管理、ブラウザAPI、永続化、既存リネーム処理と正しく接続されていることを確認する。

単体テストでは `DirectoryProvider`（ディレクトリ状態管理）の状態遷移を確認済みのため、結合テストでは実ブラウザ上の操作と画面反映を中心に確認する。

## 対象範囲

対象に含めるもの:

- `web/index.html`（WEBエントリHTML）の File System Access API 連携
- `IndexedDB`（ブラウザ内データベース）への許可済みフォルダ保存
- `DirectoryProvider`（ディレクトリ状態管理）とWEBファイルシステム連携の接続
- `web_home_screen.dart`（WEB専用ホーム画面）の左ペイン/中央ペイン/右ペイン表示
- ファイル一覧表示、フォルダ移動、パンくず移動、選択、リネームプレビュー、リネーム実行
- 既存Windows版/Android版への回帰影響

対象から外すもの:

- フォルダーリネームの実行
- OS全体のドライブ一覧表示
- 任意パス入力によるローカルフォルダ移動
- 非対応ブラウザでの直接リネーム
- 大容量フォルダの性能試験
- セキュリティ診断や脆弱性診断

## 前提環境

推奨確認環境:

| 環境 | 目的 |
|---|---|
| Chrome 最新版 | `showDirectoryPicker`（フォルダ選択API）の主対象確認 |
| Edge 最新版 | Chromium系ブラウザでの互換確認 |
| Firefox 最新版 | 非対応ブラウザ表示の確認 |
| Windows 11 | ローカルフォルダ連携の主対象OS |

起動方法:

| コマンド | 用途 |
|---|---|
| `flutter run -d chrome`（ChromeでWEB版を起動） | 手動結合テスト |
| `flutter build web`（WEBビルド） | ビルド成果物確認 |
| `flutter test`（全テスト実行） | 既存回帰確認 |
| `flutter test test/web/core/web_directory_provider_test.dart`（WEB Provider単体テスト） | WEB状態管理の回帰確認 |

## テストデータ

テスト用フォルダをローカルに作成する。

例:

```text
renamery-web-it/
  001_old.txt
  002_old.txt
  photo_old.jpg
  duplicate.txt
  sub-folder/
    child_old.txt
  empty-folder/
```

注意:

- 実ファイル名変更を伴うため、既存の重要ファイルでは実施しない。
- OneDrive同期配下で試す場合は、同期中アイコンやロック状態の影響が出る可能性を記録する。
- 同一テストを再実行できるよう、変更前のテストフォルダをコピーしておく。

## 優先度定義

| 優先度 | 意味 |
|---|---|
| P0 | リリース前に必須。失敗時はWEB版利用不可またはデータ破損リスクがある |
| P1 | 主要導線。失敗時はWEB版の使い勝手または信頼性に大きく影響する |
| P2 | 補助導線。失敗時も回避策がある |

## Playwright実行時の注意

Playwrightで実施する場合、`showDirectoryPicker`（フォルダ選択API）は通常のファイルアップロードとは異なるため、完全自動化しづらい。

自動化では以下のどちらかを採用する。

| 方式 | 内容 |
|---|---|
| JSブリッジのモック | `window.renameryFs`（WEBファイルシステムブリッジ）をテスト用に差し替える |
| 手動併用 | 起動、表示、バリデーションは自動化し、フォルダ選択と実リネームは手動確認する |

推奨は、結合テスト初期では手動併用とし、UI統合方針が固まった後にJSブリッジのモックによるE2E自動化を追加すること。

## E2E自動化ロードマップ

このリポジトリでは `package.json`（Node依存定義）、`playwright.config.ts`（Playwright設定）、`e2e/web/renamery_web.spec.ts`（WEB E2Eテスト）を使って、E2E自動化を段階的に拡張する。

| 段階 | 内容 | 目的 |
|---|---|---|
| Phase 1 | ビルド済み `build/web`（WEBビルド成果物）を起動し、初期表示と非対応案内を確認 | Playwright導入時の最小スモークテスト |
| Phase 2 | `window.renameryFs`（WEBファイルシステムブリッジ）をテスト用モックに差し替える | フォルダ選択なしで一覧、選択、プレビュー、バリデーションを自動化 |
| Phase 3 | 手動準備したテストフォルダで実ブラウザ確認を併用する | File System Access API と実ファイルリネームの最終確認 |

Phase 2 のモックは以下の振る舞いを持たせる。

| メソッド | モック内容 |
|---|---|
| `isSupported`（対応判定） | テストごとに `true` / `false` を切り替える |
| `pickDirectory`（フォルダ選択） | 固定のルートフォルダ情報を返す |
| `listSavedDirectories`（保存済みフォルダ一覧） | テスト用フォルダ候補を返す |
| `requestDirectoryPermission`（フォルダ権限要求） | `granted` / `denied` を切り替える |
| `listDirectory`（フォルダ内一覧） | テスト用ファイル/フォルダ一覧を返す |
| `renameFile`（ファイル名変更） | メモリ上の一覧を更新し、重複名や失敗ケースでは例外を返す |

最初に自動化するケース:

- WEB-IT-001（ChromeでWEB版が起動する）
- WEB-IT-003（非対応ブラウザの案内）
- WEB-IT-030（単一選択）
- WEB-IT-031（全選択/解除）
- WEB-IT-040（文字列置換プレビュー）
- WEB-IT-042（連番プレビュー）
- WEB-IT-050〜054（バリデーション）
- WEB-IT-064（実行不可状態）

Playwright構成:

| ファイル | 役割 |
|---|---|
| `package.json`（Node依存定義） | `@playwright/test`、`http-server`、実行スクリプトを定義 |
| `playwright.config.ts`（Playwright設定） | `webServer` で `build/web`（WEBビルド成果物）を配信 |
| `e2e/web/renamery_web.spec.ts`（WEB E2Eテスト） | WEB版のスモーク/モックE2Eを配置 |

設定追加時は、既存のFlutter検証と合わせて以下を実行する。

```text
flutter test
flutter build web
npx playwright test
```

通常は以下のnpmスクリプトを使う。

```text
npm run test:e2e
npm run test:e2e:full
```
